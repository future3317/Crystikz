你现在不是在完成一个简单脚本，而是在开发一个之后会长期用于科研论文制图的、可维护、可扩展、可复现的 Python scientific visualization package。

请直接在当前 repository 中完成设计、重构、实现、测试、文档、示例和验证。不要只给我方案，不要停留在架构设计，不要仅创建 skeleton，不要让我逐个确认模块后再继续。

如果当前项目中已经存在 demo、`crystal_tikz.py`、`crystal_tikz/`、示例 notebook、Markdown demo 或实验代码，首先完整阅读它们，理解已有设计，然后在保留有价值接口的基础上重构。

## 一、最终目标

开发一个真正可用于科研论文的晶体可视化工具包。

其核心理念必须是：

`Crystal data / Structure`
→ `canonical internal model`
→ `analysis + geometry construction`
→ `backend-independent Scene`
→ `multiple rendering backends`
→ `publication-ready PDF/SVG/PGF/TikZ/PNG/TIFF`

不要把所有晶体逻辑继续直接写成 TikZ 字符串。

TikZ 只是一个 renderer/backend，而不是整个系统的内部数据结构。

最终包应该满足以下场景：

1. 用户给一个 CIF/POSCAR/pymatgen Structure/ASE Atoms，就能直接得到漂亮的论文晶体结构图。
2. 自动识别 PBC、空间群、元素、晶格、周期镜像。
3. 自动生成 bonds、coordination polyhedra、unit-cell edges。
4. 用户可以非常方便地画：

   * ball-and-stick
   * coordination polyhedra
   * unit cell
   * supercell
   * crystal axes
   * Miller planes
   * polarization vectors
   * forces
   * magnetic moments
   * phonon/displacement arrows
   * defects
   * selected sites
   * bond lengths / angles
   * Wyckoff labels
   * reciprocal lattice / Brillouin zone
5. 能导出真正适合论文的矢量 PDF/SVG/PGF/TikZ。
6. 对复杂 3D 光照场景还能使用 PyVista/VTK、Fresnel 或 POV-Ray 产生高质量透明 PNG/TIFF。
7. 输出尺寸、字体、线宽、DPI、透明背景、legend、panel label 等全部可控。
8. 同一 Figure 可以保存一份 YAML/JSON recipe，以后完全复现。
9. 有 Python API，也有 CLI。
10. 包安装后可以直接用于未来几十篇图，而不是针对一个 BaTiO3 demo 写死。

建议作为主要 crystallographic semantic backend。

* oxidation state
* site properties
* magnetic moments
* slabs/surfaces where appropriate

不要复制 pymatgen 内部实现。

## 3.2 spglib

用于：

* space-group detection
* standardized cells
* primitive cells
* equivalent atoms
* symmetry dataset
* Wyckoff information
* magnetic symmetry where feasible

可以通过 pymatgen 的封装，也可以在需要更底层结果时直接使用 spglib。

`ASE Atoms <-> internal CrystalStructure`

利用 ASE：

* extxyz
* CIF
* trajectory
* neighbor lists
* natural cutoffs
* POV-Ray integration

ASE 应该是 optional dependency，而不要让核心 package 因 ASE 未安装而无法 import。

使用 `scipy.spatial`：

* ConvexHull
* KDTree/cKDTree
* Voronoi/Delaunay（合理场景）

尤其 coordination polyhedra 不要人工写死 octahedron faces。

应从实际 neighbor coordinates 自动构造 hull。

## 3.5 SeeK-path

作为 optional reciprocal-space dependency。

支持：

## 3.6 Matplotlib

作为主要 publication 2D/vector backend 之一。

必须支持：

* PDF
* SVG
* EPS
* high-DPI PNG
* transparent background
* exact figure size
* LaTeX-compatible typography
* PGF backend

研究并正确配置：

* `pdf.fonttype`
* `ps.fonttype`
* SVG text/path policy
* PGF
* `text.usetex`

## 3.7 TikZ / PGF

保留现有 demo 最有价值的部分，但重构为独立 backend：

`TikzRenderer`

它必须只接收统一 Scene，而不能自己承担 crystallographic analysis。

支持：

* snippet `.tex`
* standalone `.tex`
* compile PDF
* optionally SVG conversion
* safe LaTeX escaping
* opt-in raw LaTeX labels
* consistent preamble
* automatic library collection

## 3.8 PyVista / VTK

作为 optional advanced 3D renderer。

用于：

* complex polyhedra
* meshes
* clipping
* isosurfaces
* lighting
* shadows
* transparent background
* high-resolution rendering

PyVista 支持 SVG/EPS/PS/PDF/TEX graphic export，但必须注意：

**3D 内容有可能在所谓 vector graphic 中被 rasterized。**

因此不能看到 `.pdf` 扩展名就宣称是 pure vector。

实现 export metadata / preflight：

例如记录：

`vector_status = "pure" | "hybrid" | "raster"`

并在文档明确告诉用户。

## 3.9 Fresnel / POV-Ray

作为 optional photorealistic backend。

适用于：

* publication-quality ray tracing
* shadows
* ambient occlusion style
* transparent high-DPI raster images

## 3.10 Crystal Toolkit

`Scene`

`Cylinders`
`Arrows`

等设计。

可以借鉴它的 scene-graph philosophy。

但是不要直接把 Dash/React/Web UI 整套引入核心 package。

如果使用其代码/API，严格遵循 license；不要复制大段实现。

# 八、周期边界条件必须真正正确

这是核心科研正确性要求。

处理：

* atoms exactly on cell faces
* duplicated corner atoms
* periodic bonds
* jimage
* supercell
* atoms outside `[0,1)`
* complete coordination polyhedra crossing cell boundaries

提供 boundary modes，例如：

* `"unit_cell"`
* `"complete_bonds"`
* `"complete_polyhedra"`
* `"include_images"`
* `"clip"`

* source site index
* image offset `(i,j,k)`
* identity
